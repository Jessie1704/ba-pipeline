# Changelog

All notable changes to BA Pipeline and to its predecessors, BA Guardian Angel (1.x) and BA Copilot (0.x). Versions
follow semantic versioning: a **major** bump changes artifact formats or the audit log in a way existing features
must migrate; **minor** adds stages, checks or profiles; **patch** fixes wording and bugs.

## 1.0.0 — 2026-11-12 — BA Pipeline

First release under the new name, in a new repository (`Jessie1704/ba-pipeline`). The workflow, its rules and the
data formats are those of BA Guardian Angel 1.2.1; nothing in a project's requirements has to change.

### Changed
- **Name:** BA Guardian Angel → **BA Pipeline**. The commands stay `/ba-…` and `ba …`.
- **Kiro Power:** name and entry skill `ba-pipeline`; marker file `ba-pipeline.package`; import from
  `https://github.com/Jessie1704/ba-pipeline/tree/main/kiro-power`.
- **Generated files:** marker "generated by BA Pipeline", block `<!-- BA-PIPELINE:START -->`, Cursor rule
  `.cursor/rules/ba-pipeline.mdc`, Kiro steering `.kiro/steering/ba-pipeline.md`. Files and blocks written by BA Guardian
  Angel or BA Copilot are recognised and replaced in place; their old Cursor/Kiro files are removed.
- **Installer:** `.ba/config.json` records `product`. A project on BA Guardian Angel 1.x or BA Copilot 0.x updates to
  BA Pipeline 1.0.0 with `install.py update` (no `--force`: a predecessor's version numbers are not compared).
- Events log the tool as `ba-pipeline <version>`; "BA Pipeline" is one of the AI names that can't approve.

### Included (from BA Guardian Angel 1.2.1)
- 20 stages from intake to release (Define, Deliver, formal documents, learning an existing system), human gates per
  mode, an independent review, a live RTM, KPIs, status/dashboard/Excel, and a hash-chained audit trail.
- A self-contained Kiro Power and adapters for Claude Code, Codex/AGENTS.md, GitHub Copilot, Cursor, Gemini CLI and
  Kiro. 202 tests (4 new, for upgrading from BA Guardian Angel).

## Before BA Pipeline

### BA Guardian Angel 1.2.1 — 2026-11-12 — self-contained Kiro Power; independent review of 1.2.0

#### Changed
- **The Kiro Power is self-contained.** Import it (from GitHub: `…/tree/main/kiro-power`, or a folder) and call its
  skills: the workflow runs from the power's `package/` folder, the project keeps only its data. Every stage skill
  carries its playbook; the entry skill carries the operating manual and the routing table. A skill finds the
  package next to it, through `.ba/config.json` → `package`, or by the marker file `ba-guardian-angel.package`
  (PowerShell and shell commands given). `ba-setup` is now optional: it pins a copy in `.ba/`, which the skills then
  prefer. New `ba where [--save]`; `ba context` prints the workflow folder and the command to use.

#### Fixed (independent review of 1.2.0)
- **G1 Mode:** the rules use the latest mode change by the PO or business owner; editing the cell alone changes
  nothing and the *gates* check FAILs the mismatch; a cell with notes ("controlled · (PO, D-090)") or in Vietnamese
  ("Kiểm soát", "nhanh") is read correctly; a cell naming no mode FAILs.
- **G2 Gates table:** found by its columns or a heading naming Gates/Cổng; a missing table or a row without its stage
  number FAILs instead of being skipped.
- **G3 Names:** no prefix matches ("Nguyễn Thị" is nobody); a given name of two words matches only if no one else on
  the status page has it; one person per actor; role words are not actors (the log keeps `actor_resolved`); notes
  after a name ("- PO", "qua email") and names without diacritics are understood; forms of address are dropped only
  when two words remain ("Anh Tuấn" stays a name); the BA conflict needs the whole name.
- **G4 Kiro:** `TERM_PROGRAM=kiro` marks events as `via: assistant:kiro` (with the model); `ba approve` is refused there.
- G5 decision dates in dd/mm/yyyy; an undated decision can't close a gate. G6 `ba approve` needs a real terminal
  (a redirected stdin is refused); README wording says the tools detect, not prevent. G7 severity columns `Sev` /
  `Mức độ`; a Defects table without severity WARNs. G8 Vietnamese rejections ("không duyệt", "chưa đạt", "trả lại")
  never count as approvals. G9 Vietnamese mode words. G10 `install.py update --tools` adds tools instead of replacing
  them; `init` keeps settings from a power-mode `.ba/config.json`. G11 no hard-coded power path. G12
  `build_power.py` is not copied into projects or the power. G13 the example feature no longer carries the author's
  account name or session IDs (its audit chain was rebuilt).
- 23 new tests (198 in total).

### BA Guardian Angel 1.1.1 — 2026-11-12 — independent review of 1.1.0

Fixes the 5 Major and the proven Minor findings of the independent review of 1.1.0. No licence is granted any more
(all rights reserved).

#### Fixed
- **Approver identity** (N1, n11, n12): people are compared as whole names (NFC, forms of address such as "chị",
  "anh", "Mr" and "(role)" notes removed), a given name of two words or more ("Lan Anh"), the `STK-` ID resolved
  through *Stakeholders*, or "PO" / "business owner" resolved through *Governance* — never a fragment ("a", "An",
  "Thị"). A short BA name no longer blocks the PO. *Gate approvers* may map gates to people (`3,8,9: STK-02; 11:
  STK-05`); area owners approve only outside gates.
- **The rules of the game** (N2): `settings.changed` about the Mode or `human_gates` is a guarded event — only the PO
  or the business owner, with their own `D-`; the *gates* check accepts only such events; a `human_gates` config
  change needs a workspace event run by a person outside the AI tool.
- **Evidence for approvals** (N3): refs are IDs only; a guarded event must cite a `D-` from the *Decision log*
  decided by the actor (a source alone no longer counts); a gate's `D-` can't predate the latest `stage.started` of
  that stage; `approval.recorded` needs a feature.
- **Gate values** (N4, n8): *Gates* results must be canonical; "Đạt", "Pass", "Approved", "✅ Passed" FAIL and are
  still compared with the log; the dashboard uses the same reading. Review verdict, score and severities are read
  without markdown, emoji or case ("🔴 critical", "Blocker", "**Pass**"); Pass below 80 FAILs; a deferred Major
  needs the PO's or business owner's `D-`.
- **Relayed approvals** (RA): a human gate the AI tool relayed without a `SRC-` WARNs (FAILs in controlled mode).
  New `ba approve <feature> --gate | --doc | --mode --as <name> --decision D-NN`: refused inside an AI tool and
  without a terminal, the approver types their name; required for human gates in controlled mode; document
  approvals are pinned to the file's hash.
- RTM (n1, n2, n3): a 1.0 combined row keeps its result on the first test only; evidence must be a link, a file, a
  `SRC-`, a ticket or run ID (not "n/a", "see above", "tested 2026"); one `result.recorded` event per result with
  structured fields, and the check compares the *Result log* with them.
- Documents (n4): an approval must name the exact file, not be a rejection, come from the PO or business owner,
  and (with `ba approve`) the file must be unchanged since.
- Knowledge (n5): "đ" kept as "d" in folder names; a name with no Latin letters is refused; *Verified* needs a
  person and a date (ISO or dd/mm/yyyy).
- Routing (n6): "trạng thái" no longer maps to two stages; rows for status, dashboard, Excel, KPI, RTM and approvals.
- Audit fields (n7): inside an AI tool `BA_VIA=cli` is ignored; `model` is recorded only for what an AI tool ran;
  `session` reads `CLAUDE_CODE_SESSION_ID`; hook and sync records carry `reported_by` and `via`.
- Vietnamese ambiguity (n9): "họ và tên đầy đủ", "một - nhiều", "sớm nhất", "chuyển tiền nhanh", "số nguyên",
  "định kỳ lúc 02:00" are not flagged.
- UAT thresholds (n10): read in Vietnamese ("độ phủ 100, tỉ lệ đạt 95"); an unreadable value is "not set"; a passed
  gate 11 with thresholds not met FAILs.
- Template and migration (n14, m6): no example IDs in the status template; placeholder rows hidden; the 0.5 Scope
  gate wording migrates.
- `MANUAL.md` 22.4 KB → 20.8 KB: answer modes moved to `reference/answers.md`, enforcement details to
  `reference/audit.md`. 27 new tests (169 in total).

#### Removed
- The MIT licence file and its mentions; the v1.1.0 release and tag (v1.1.1 supersedes it).

- **Handoff templates and check agree** (M3): every handoff template has the `## Skipped stages & known gaps` heading;

- **RTM** (M4, m3, m4, m5): one row per AC and test (1.0 combined rows are split); *Recorded by* can't be the assistant;

- **KPIs** (M5, m9): pass rates are Pass / (Pass + Fail + Blocked); requirement completeness, AC testability, AI

- Minor: Excel export escapes quotes and caps cells at 32,767 characters (m1); `status --html` creates its folder (m2);

### BA Copilot 0.5.0 — 2026-11-05 — foundations, answer modes, lean context

From the Demo-BA pilot in Kiro (slow turns, success metrics never asked, no business owner or Culture-module
owner, questions answered in six trickling rounds). Three root causes, fixed at the root:

#### Added — foundations and governance (scope and MVP were decided without goals or a decider)
- MANUAL rules 3–4: **foundations before features** (problem and cost, success metrics with baseline and target,
  business owner, PO, an owner per area, hard constraints) and **who decides is recorded, not guessed**
  (escalation to the business owner, role conflicts when the BA is also PO, provisional decisions revisited).
- Priority **Decision-critical**: the answer changes scope, the MVP or who decides; blocks the Scope gate.
- `_status.md` → *Governance* table; *Decides on* column for stakeholders; `01-intake.md` → *Foundations*;
  `03-scope.md` in-scope *Owner* and *Profile* columns (goal or `mandatory: … (SRC-/D-)`) and an *MVP by value*
  table, the one place the release slice is recorded.
- Intake step 4b (foundation questions first), governance capture in step 4; Scope re-decides provisional
  decisions against the goals, area owners confirm, conflicts go to the business owner.
- `ba check` **governance** (business owner, PO and every named area have an owner — WARN before Scope, FAIL
  after; every goal's Metric, Baseline and Target filled, "unknown" needs a plan to measure; Foundations rows have
  a status; every `IS-` has a goal and an owner; role conflicts) and **audit** (every `D-` in the audit log, no unrecorded file change).
- Gap lenses 1–2, Definition of Ready, quality rubric and reviewer persona check foundations and governance.
  The scope-freeze card, `ba-next`, `ba-start` and the skip table all treat them as first-class, so they can't be
  parked or skipped unnoticed.
- `small-change` 1.1 relaxes the foundations: the PO stands in as business owner (the governance check accepts
  it), the success metric may be waived by the PO (`D-`), other teams' owners only when their area changes, no
  *MVP by value* table.

#### Added — answer modes (answers trickled through the chat)
- *Answer mode* preference: **walkthrough** (*Questions per message* at a time, default 5, with suggestions and a
  progress line "Questions 6–10 of 24", from a round fixed up front with `ba answers new --chat`; "★ for the
  rest" accepts the remaining suggestions) or **file**.
- `ba answers new <feature> [--who …] [--ids …]` writes a tick-box form `answers/round-NN.md`; the BA saves and
  says "done"; `ba answers read` prints the answers compactly and files the form as the next `SRC-`.
- **A round is complete before the first question**: the full sweep is finished first, follow-up questions go
  inside the options they depend on, questions raised mid-round join the next message if Blocking or
  Decision-critical and otherwise wait for the next round, Nice to know is parked. Editing artifacts in place
  ("done") is a first-class path.
- `ba answers read` handles every form in `answers/`, leaves blank ones in place, and reads answers written under
  an option. `ba answers new` notes questions already out in a form not read yet, and `--chat` numbers the round
  by priority, then person.

#### Changed — lean context and bookkeeping (≈ 29 KB always loaded, 72 KB artefacts re-read, 5–10 shell calls a turn)
- `ba turn <feature> --events <file|-> [--gate --stage …]`: one call per turn validates and logs all of the
  turn's events, rewrites the Open-items snapshot from the register and records file changes; `--gate` runs and
  logs `ba check`. Events are still logged every turn — only `ba check` moves to the gates.
- `ba context <feature> <stage>`: status, gates, governance, revisit triggers, open items, skip impact and only
  the profile sections the stage needs, in one read.
- `ba questions archive <feature>` moves answered questions and settled assumptions to `02-closed.md` (the
  register spans both files). Stored ready-to-send packs removed from `02-questions.md`.
- `MANUAL.md` 22.0 KB → 14.4 KB; details moved to `core/reference/` (`ids.md`, `audit.md`, `checks.md`).
  Generated instruction blocks are shorter (AGENTS.md block 3.7 KB → 2.6 KB) and point to `ba context`/`ba turn`; the
  stage table uses short phrases in the BA's own words.
- Stage files start with `ba context` and end with `ba turn`, instead of reading whole files and logging each
  event with its own command. Model, Stories and Spec name the sections they build on (plus the glossary);
  `ba context` gives drafting stages the open questions' text so they aren't written as facts. Checks run and
  are logged at the gate (`ba turn --gate`, Review included); quick unlogged `ba check --only …` while drafting.

Measured on a copy of Demo-BA (`msb-employee-services`): always-loaded instructions in Kiro 25.9 KB → 17.1 KB;
start-of-stage reads for Elicit / Scope / Stories ~ 97–99 KB → 10.0–15.6 KB plus targeted reads;
`02-questions.md` 37.5 KB → 22.9 KB after archiving; bookkeeping 5–10 commands a turn → 1.

#### Migration
- `install.py update` adds *Answer mode*, *Questions per message* and the *Governance* section (PO copied from the existing field) to every
  `_status.md`, and reminds you per feature to fill in the business owner and every area with its owner; `ba context`
  repeats it until an area is named. Features with no scope yet are also pointed to the foundation check. From Scope on, `ba check` fails without the business owner.
- 41 new tests (85 in total).

### BA Copilot 0.1.0 — 2026-10-26 — first packaged version

Packaged from the Claude Code workspace where the workflow was built and piloted.

#### Changed
- Core is tool-neutral: `core/MANUAL.md` (was `CLAUDE.md`) and `core/stages/*.md` (were Claude Code skills).
  Tool-specific wording (sub-agent calls, "Bash tool", Write/Edit tools, `.claude/` paths) replaced by
  capabilities; §0 of the manual explains how any tool maps them.
- Independent review works without sub-agents: a new chat or another tool with a ready-to-paste prompt;
  same-conversation review caps the verdict at *Conditional*.
- Paths resolve `.ba/local/` before `.ba/core/`, so projects override templates, checklists and profiles
  without editing the core.
- Scripts ported from Windows PowerShell 5.1 to `tools/ba.py` (Python 3.9+, standard library only):
  `ba check`, `ba audit event | sync | verify | hook`. The audit log format and hash chain are unchanged, so
  logs written by the PowerShell scripts still verify.

#### Added
- `ba audit sync`: records file changes by hash at the end of each stage, for tools without post-edit hooks
  (and edits made outside any tool).

#### Lessons from the pilot (expense claims, fictional) that shaped 0.1.0
- **Drafting invents plausible facts** (bulk approve, fallback queues, retry times, dropped qualifiers such as
  "domestic" or "absent > 3 days"). → Grounding self-check in Stories and Spec, `ground` check, reviewer told
  to treat invented facts as Critical.
- **Fix rounds after a review invent facts too** (score fell 75 → 72). → Grounding re-check on changed lines
  before any re-review.
- **Status tracking drifted**: `_status.md` was written late and its counts were wrong. → Stage protocol step 0;
  `ba check status` compares the snapshot with the register.
- **Formatting hid open items** (`**Blocking** (…)` cells were missed). → Tables parsed by column name with
  markdown stripped; register values must start with a canonical word.
- **Lite runs were under-rated**: UX Lite logged as Medium where the rules made it Critical. → Adjusted
  severity on the stage card; Lite minimum-mitigation is a checklist.
- **Elicitation did not converge** (questions 33 → 57 over two rounds). → Round counter, scope-freeze card from
  round 3, PO bulk acceptance of Low assumptions.
